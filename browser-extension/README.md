# RelayOps 登录配对助手 v1.3.8

1. 在 Chromium 浏览器打开扩展管理页并启用开发者模式。
2. 选择“加载已解压的扩展程序”，指向本目录。
3. 在 RelayOps 的凭据页面为上游生成一次性配对码。
4. 打开该上游并由用户正常完成登录、二步验证或验证码。
5. 点击扩展，填写 RelayOps 地址和配对码，再确认配对。

RelayOps 默认本机地址为 `http://127.0.0.1:18180`，扩展会保留上次成功使用的地址，但不会扫描其他端口。点击后先验证该地址的 RelayOps 健康契约，再验证配对码仍为 `pending`，最后确认当前标签页与配对码绑定的上游 origin 完全一致。三项全部通过后才会读取凭据。

扩展只读取已获授权 origin 的 Cookie 和经过名称筛选的登录存储项，并把该 origin 随凭据提交。对于把短期 access token 仅保存在页面内存的新版 NewAPI，扩展会先通过同源 `/api/status` 确认站点合同，再使用当前浏览器 Cookie 调用同源认证刷新接口，仅提取 access token、用户 ID 和到期时间。它不会读取密码、浏览器密码库或未授权站点，也不会跨域跟随重定向。配对码五分钟内只能建立一次凭据，成功后转为仅绑定该 RelayOps 实例、供应商和 origin 的浏览器托管令牌，不能访问管理 API 或修改价格。

后台每分钟只向本机 RelayOps 查询一次是否有明确的核心授权失效证据。只有服务端回答需要接管，且对应上游页面已经打开时，扩展才从该标签页捕获候选会话；候选还必须通过服务端只读能力验证和并发版本校验，失败时旧凭据与旧数据保持不变。同一份已经被拒绝的页面会话会在本地去重，避免每分钟重复提交；管理员完成登录或人机验证后，会话指纹变化并立即重试。扩展不会打开网页、填写账号密码、点击验证码或绕过二步验证。管理员在上游页面正常完成人机验证后，后续捕获和复采无需再次确认。

托管令牌只会发送给本机 HTTP RelayOps（`localhost`、`127.0.0.1`、`[::1]`）、Tailscale 私网 `100.64.0.0/10` 内的 HTTP RelayOps，或启用 HTTPS 的远程 RelayOps；扩展会拒绝把托管令牌发往其它远程 HTTP 地址。

在扩展弹窗点击“停止当前站点托管”，或在 RelayOps 凭据页关闭托管，都能立即撤销服务端令牌。上游会话仍有效、可选用量接口 403、网络故障或目录结构变化时不会触发会话替换。
